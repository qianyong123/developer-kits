# 砺 · 登录模块 — 技术方案

> 版本：v0.1（本期）  
> 日期：2026-08-13  
> 配套文档：[公共技术方案](./公共技术方案.md)、[公共需求](./公共需求.md)  
> 适用范围：账号注册 / 登录 / Token 鉴权演示，CloudBase 云函数练手

> ⚠️ 本模块是「砺」第一个引入后端能力的模块，突破了「纯前端、无后端、无数据库」的公共假设。公共技术方案尚未同步更新，本节文档以本文件为准。

## 1. 背景与目标

- 主要目的：**练习 CloudBase 云函数**，用登录功能作为载体，完整走通「前端 → 云函数 → 数据库 → Token 鉴权」链路。
- 目标范围：用户名密码注册、登录、Token 签发与校验、登录态保持、退出登录。
- 明确取舍：**故意不用 CloudBase 官方登录能力**（用户名密码/微信等），而是自建云函数登录逻辑，以达成学习目标；生产项目应优先评估官方登录。
- 环境：CloudBase 环境 `kits-dev-d4g4yxxnw8e41a263`（ap-shanghai，体验版，PostgreSQL 型）。

## 2. 总体架构

```mermaid
graph LR
  LoginPage[登录页 /login] --> SDK[@cloudbase/js-sdk callFunction]
  SDK --> AuthFn[auth 云函数 Event Function]
  AuthFn --> PG[(PostgreSQL users 表)]
  AuthFn -->|签发/校验 HMAC Token| LoginPage
```

- 前端只通过 `app.callFunction({ name: 'auth', data })` 调用云函数，**不直连数据库**。
- 浏览器侧先建立 CloudBase **匿名会话**（网关传输通道），业务鉴权由云函数自签 Token 完成，二者是两层独立体系。
- 云函数通过 **PG REST API + service_role API Key** 访问 PostgreSQL（云函数运行时免密凭证不是 service_role，无法直接访问 PG，这是实测得出的结论）。

## 3. 数据设计（PostgreSQL）

### 3.1 表结构

迁移文件：`cloudbase/migrations/20260813034444_add_users.sql`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGSERIAL PRIMARY KEY | 用户 ID（Token 中的 uid） |
| username | TEXT NOT NULL UNIQUE | 用户名，3-20 位字母/数字/下划线 |
| password_hash | TEXT NOT NULL | scrypt 加盐哈希（64 字节 hex） |
| salt | TEXT NOT NULL | 16 字节随机盐（hex） |
| created_at | TIMESTAMPTZ NOT NULL DEFAULT now() | 注册时间 |

### 3.2 权限

```sql
GRANT SELECT, INSERT, UPDATE, DELETE ON public.users TO service_role;
GRANT USAGE, SELECT ON SEQUENCE public.users_id_seq TO service_role;
```

- 仅授予 `service_role`（云函数数据层使用），不授予 `anon` / `authenticated`，前端无法直接读写。
- 表不开启 RLS：只有函数访问，行级策略无意义；若后续放开浏览器直连，必须补 GRANT + RLS。

## 4. 云函数设计

目录：`cloudfunctions/auth/`

| 项 | 值 | 说明 |
| --- | --- | --- |
| 类型 | Event Function | 浏览器 SDK 调用，非 HTTP 暴露 |
| 运行时 | Nodejs18.15 | 支持全局 `fetch` |
| 入口 | `index.main` | |
| 依赖 | 零第三方依赖 | Node 内置 `crypto` + 全局 `fetch` |
| 环境变量 | `TOKEN_SECRET`、`CLOUDBASE_API_KEY`、`ENV_ID` | 见 §6.3 |

### 4.1 接口协议

统一响应：`{ code, message, data }`，`code`：0 成功 / 1 业务错误 / 401 未登录或过期 / -1 服务异常。

| action | 入参 | 出参 data |
| --- | --- | --- |
| register | `{ username, password }` | `{ token, user: { uid, username, createdAt } }` |
| login | `{ username, password }` | `{ token, user: { uid, username, createdAt } }` |
| me | `{ token }` | `{ user: { uid, username, createdAt } }` |

### 4.2 密码学

- 密码哈希：`crypto.scrypt(password, salt, 64)`，盐每次注册随机生成（16 字节 hex），**不存明文**。
- Token：HMAC-SHA256 签名，格式 `base64url(payload).base64url(signature)`，payload 为 `{ uid, exp }`，有效期 7 天；校验时恒定时间比较签名。
- 登录失败统一返回「用户名或密码错误」，避免用户名枚举。

### 4.3 数据库访问（PG REST）

```text
https://{ENV_ID}.api.tcloudbasegateway.com/v1/rdb/rest
```

- 查询：`GET /users?username=eq.{username}&select=*`
- 写入：`POST /users` + `Prefer: return=representation`（回写含自增 id）
- 鉴权头：`Authorization: Bearer {CLOUDBASE_API_KEY}`（service_role，绕过 RLS）

## 5. 前端设计

### 5.1 目录

```text
src/features/auth/
├─ AuthPage.tsx / AuthPage.module.css   # 登录/注册页（复用 Button、Notice，亮暗主题）
├─ store.ts                             # zustand 登录态：checking/guest/authenticated
├─ api.ts                               # register/login/me 类型化封装
├─ types.ts                             # AuthUser / AuthActionResult
├─ storage.ts                           # localStorage token 读写
└─ lib/formatDate.ts                    # 注册时间格式化（YYYY-MM-DD HH:mm）
src/shared/lib/cloudbase.ts             # SDK 初始化 + 匿名会话保证
src/shared/i18n/zh/auth.ts              # 文案命名空间
```

### 5.2 SDK 封装与调用链

```ts
cloudbase.init({ env, region: 'ap-shanghai', accessKey: publishableKey, auth: { detectSessionInUrl: true } })
```

- `ensureCloudbaseSession()`：`auth.getSession()` 无会话时调用 `auth.signInAnonymously()`（幂等）。
- 每次 `callFunction` 前保证会话存在；云函数调用权限规则为 `"invoke": "auth != null"`（控制台配置）。
- Token 存 `localStorage`，应用内由 zustand store 统一管理；启动时用 `me` 校验恢复。

### 5.3 路由与导航

- `src/App.tsx` 新增独立路由 `/login`（懒加载，独立 chunk），不进入工具注册表。
- `src/app/AppShell.tsx` 侧边栏底部新增「登录 / 注册」入口。

## 6. 安全设计

### 6.1 密码安全

- 数据库仅存 scrypt 哈希 + 盐，不可逆；任何人看到 `users` 表也无法还原密码。
- 密码经 HTTPS 传输，云函数内即时哈希比对、不落日志。

### 6.2 Token

- HMAC-SHA256 签名防篡改，含过期时间，`me` 每次请求都校验并回源查用户。
- 前端 XSS 可窃取 localStorage 中的 Token —— 演示层级可接受，生产建议 HttpOnly Cookie + refresh token。

### 6.3 密钥管理

| 密钥 | 归属 | 存放 | 风险等级 |
| --- | --- | --- | --- |
| publishable key | 匿名角色，公开 | 前端源码 `src/shared/lib/cloudbase.ts` | 低（公开设计） |
| TOKEN_SECRET | Token 签名 | 仅函数环境变量（控制台 / CLI 注入） | 中 |
| CLOUDBASE_API_KEY | service_role（数据库管理员） | 仅函数环境变量（控制台 / CLI 注入） | **高** |

- ⚠️ 密钥**不进入** `cloudbaserc.json` / git。函数部署后通过控制台或 CLI 注入环境变量；**重新执行 `tcb config update fn` 会用配置全量覆盖环境变量，需先重新注入密钥再更新配置。**

### 6.4 平台侧配置

- 匿名登录：控制台「身份认证 → 登录方式」开启。
- 云函数调用权限：控制台「云函数 → auth → 权限控制」，规则 `"invoke": "auth != null"`（允许匿名会话调用）。
