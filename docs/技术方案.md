# 开发工具包 · 网页版图片压缩工具 — 技术方案

> 版本：v0.1（草案）  
> 日期：2026-08-06  
> 配套文档：[需求文档](./需求文档.md)

## 1. 总体架构

纯前端单页应用（SPA），无后端、无数据库。所有图片处理在浏览器内完成，构建产物为静态文件，可部署到任意静态托管平台。

```mermaid
graph TD
  A[用户拖拽/选择图片] --> B[图片列表状态管理]
  B --> C[压缩引擎 CompressEngine]
  C --> D[Canvas 解码/重绘]
  D --> E[编码器 WebP/JPEG/PNG]
  C --> F[目标体积二分搜索]
  F --> E
  E --> G[预览与体积对比 UI]
  G --> H[单张下载 / fflate 打包 ZIP]
  C -.v0.2 可插拔.- I[AVIF WASM 编码器]
```

## 2. 技术栈

| 类别 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | React 18 + TypeScript | 长期维护，类型安全 |
| 构建 | Vite 5 | 快、产物静态、后续可加多页/懒加载 |
| 路由 | react-router-dom | 工具包多页面导航（/image、/json 预留） |
| 图片解码/编码 | Canvas API + `createImageBitmap` | 零依赖，覆盖 WebP/JPEG/PNG |
| ZIP 打包 | fflate | 轻量（≈8KB gzip），支持流式，避免 JSZip 的 ~100KB |
| 元数据（仅“保留”开启时） | piexifjs（读取 + 写入 JPEG） | 动态 import，按需加载，不影响首屏体积 |
| 状态管理 | React 内置 + Context | 规模可控，暂不引入 Redux/Zustand |
| 样式/响应式 | CSS Modules + CSS 变量 | 断点 <768px 移动端单列、≥1024px 桌面多列；不引入重型 UI 库 |
| 测试 | Vitest | 与 Vite 同生态 |
| 代码规范 | ESLint + Prettier | 工程标准配置 |

**依赖原则**：核心压缩路径只用浏览器原生能力；第三方依赖仅用于 ZIP 打包等无法原生完成的部分。

## 4. 关键设计

### 4.1 压缩引擎抽象（为 AVIF 预留）

定义统一的编码器接口，UI 只依赖接口，不依赖具体实现：

```ts
interface ImageEncoder {
  id: 'webp' | 'jpeg' | 'png' | 'avif';
  encode(source: ImageBitmap, options: EncodeOptions): Promise<Blob>;
  supportsQuality: boolean; // WebP/JPEG true，PNG false
  minQuality: number;
  maxQuality: number;
}
```

- WebP / JPEG / PNG 使用 Canvas `toBlob` 实现。
- v0.2 新增 AVIF 时，只需注册一个基于 WASM（如 `@jsquash/avif`）的 `ImageEncoder`，UI 与二分搜索逻辑零改动。
- 编码器注册表 `getEncoder(format)` 统一获取实例。
- 输出格式支持 `original`（与输入一致）：按文件类型映射 JPEG / WebP / PNG，GIF / BMP 统一转 PNG 并提示；界面默认选项为“原格式”。
- PNG 有损量化使用自研方案：**4D 预乘 alpha 直方图（RGB 各 4bit + alpha 5bit）**中位切分建调色板（每色自带 alpha，经 tRNS 输出，支持半透明渐变/光晕；退化切分自动换通道，条目 ≤256 满足 PLTE 上限）→ k-means 迭代精修（kd-tree 加速 4D 最近邻）→ 自适应颜色数（**仅目标体积模式启用**）→ 自适应 Floyd–Steinberg 抖动（预乘空间 4 通道误差扩散，边缘/全透明区域不扩散）→ 每行自适应 filter（None/Sub/Up/Avg/Paeth）→ 索引色 PNG 编码（PLTE / tRNS / IDAT，zlib 压缩），零第三方依赖；质量值映射为颜色数 16–256。

### 4.2 解码与预处理

- 使用 `createImageBitmap(file)` 解码，失败时回退到 `<img>` + Canvas。
- 通过 `image-orientation: from-image` 或 EXIF 处理保证手机照片方向正确。
- 可选最大边长限制（默认 4096px）：超过则等比例缩小，避免超大图耗尽内存。
- 处理完成后调用 `bitmap.close()` 及时释放内存。
- “保留元数据”默认关闭（默认剥离，与 TinyPNG 网页版一致）：开启时用 piexifjs 读取原图 EXIF，编码后写回 JPEG；WebP / PNG 的元数据写回在 v0.1 不支持，UI 上如实标注。

### 4.3 手动质量模式

- 质量滑块变化 → 对每张图调用 `encoder.encode(bitmap, { quality })` → 更新结果与预览。
- 大图或数量多时做**防抖（300ms）**，避免滑块拖动时高频重压缩。
- PNG 始终有损量化：质量滑块映射为调色板颜色数（16–256 色）+ 预乘空间 Floyd–Steinberg 抖动。

### 4.4 目标体积模式（二分搜索）

- 对支持质量参数的格式，在 `[minQuality, maxQuality]` 区间二分，目标为“不超过目标体积的最大质量”。
- 迭代约 7 次即可收敛到 ±1% 质量精度；每次编码前检查 `size <= targetBytes * 1.05` 提前退出。
- 搜索失败（最低质量仍超目标）→ 标记“无法达标”，按用户策略处理。
- PNG：对“调色板颜色数”做二分搜索。
- 同一批次中，每张图独立搜索（不同图片对质量敏感度不同）。

### 4.5 批量队列与并发控制

- 手写轻量信号量（或 `p-limit`，约 1KB），默认并发 2，可配置。
- 任务状态机：`pending → processing → done | error`。
- 全局参数变更 → 重新入队，已完成的图片标记为“过期结果”而非直接丢弃。
- 支持取消：用户可中断整个队列，已完成的保留。

### 4.6 ZIP 下载

- 使用 `fflate` 的 `zipSync` 或流式 `Zip`，一次性打包全部压缩结果。
- 文件名冲突处理：追加 `(1)`、`(2)` 后缀。
- 大批量时先提示“正在打包”，完成后触发浏览器下载。

### 4.7 对比预览

- 原图与压缩图使用同一 URL/对象保存，并排展示体积与压缩率。
- 滑动对比（拖拽分割线）用于细节比较，缩放使用 `object-fit: contain` 容器。
- 预览 Blob 用 `URL.createObjectURL` 生成，组件卸载时释放。

### 4.8 响应式与触控

- 布局策略：桌面端为“侧边设置栏 + 多列卡片网格”；移动端为单列 + 抽屉式设置面板，断点与间距统一收敛到 CSS 变量。
- 拖拽上传降级：移动端（`pointer: coarse`）隐藏拖拽提示，点击即选择文件。
- 滑动对比组件统一使用 Pointer Events，鼠标与触摸共用一套逻辑。
- 表格/列表在移动端改为卡片布局，避免横向溢出。

## 5. 性能与内存策略

- 解码后的 `ImageBitmap` 用完即 `close()`。
- 批量处理采用“一次只保留少量原图解码结果”的流水线，避免同时驻留所有大图。
- 预览缩略图单独生成小尺寸版本，不直接复用全尺寸压缩结果。
- 处理逻辑全部 `async`，UI 线程不被长任务阻塞；必要时用 `requestIdleCallback` 分摊非紧急工作。
- 若内存占用过高（页面卡顿/崩溃风险），记录并提示用户分批处理。

## 6. 浏览器兼容性

| 能力 | 最低支持 | 说明 |
| --- | --- | --- |
| `canvas.toBlob('image/webp')` | Chrome 50 / Safari 16+ 等 | 主路径 |
| `createImageBitmap` | 现代浏览器 | 有降级方案 |
| AVIF 编码 | 无原生支持 | v0.2 用 WASM 解决 |

- Safari 16 以下 WebP 编码不可用 → 自动降级提示改用 JPEG。
- 以桌面 Chrome / Edge 与移动端 Safari / Chrome 为主要目标，Firefox 做兼容性验证。

## 7. 部署方案

**结论先行：纯前端静态站点，不需要云服务器（ECS/轻量服务器），不需要安装 Node、Nginx 等任何环境。** 选择支持静态托管的平台，把构建产物（`dist/`）托管上去即可。

### 7.1 可选方案对比

| 平台 | 成本 | 部署方式 | 国内访问 | 备注 |
| --- | --- | --- | --- | --- |
| Vercel | 免费 | 连 GitHub 自动构建 | 一般（时快时慢） | 最省事，适合快速上线验证 |
| Cloudflare Pages | 免费 | 连 GitHub 自动构建 | 一般（线路不稳定） | 免费额度大，无需绑卡 |
| Netlify | 免费 | 连 GitHub 自动构建 | 一般 | 同 Vercel |
| GitHub Pages | 免费 | 推送分支自动构建 | 一般 | 无需额外平台，功能最简单 |
| 阿里云 OSS + CDN | 按量计费（个人使用每月几元量级） | 上传静态文件或 CI 同步 | 快 | 需备案域名，国内正式上线首选 |
| 腾讯云 COS + CDN | 按量计费 | 同上 | 快 | 同阿里云，按需选择 |

### 7.2 推荐路径

1. **快速验证（现在）**：代码推到 GitHub，接入 Vercel 或 Cloudflare Pages，一个分支推送即自动上线，免费且零配置。
2. **国内正式上线（有域名后）**：购买域名并备案，用阿里云 OSS 静态网站托管 + CDN 加速，构建产物直接同步到 OSS Bucket（可用 GitHub Actions 或 `ossutil` 一键同步），无需在服务器上安装任何东西。

### 7.3 部署无关性

由于是纯静态站点，部署平台可以随时切换：换平台只影响域名和构建配置，代码零改动。v0.1 阶段不绑定任何特定平台。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 超大图/大量图片导致内存暴涨 | 浏览器崩溃 | 最大边长限制、并发控制、流水线释放 |
| 已压缩过的图片无法达到目标体积 / 重编码后变大 | 用户困惑 | 明确提示“无法达标”；压缩后大于原图时自动保留原图 |
| PNG 有损量化有轻微画质损失 | 保真敏感场景不满 | 量化结果可对比预览；对保真有硬性需求建议转 WebP/JPEG |
| Safari WebP 编码缺失 | 功能不可用 | 自动降级 + 提示 |
| 目标体积模式耗时（每张多次编码） | 批量慢 | 并发 + 二分提前退出 + 进度反馈 |
| WebP 元数据写回能力有限 | “保留元数据”效果不一致 | UI 标注支持范围（仅 JPEG），避免误导 |
